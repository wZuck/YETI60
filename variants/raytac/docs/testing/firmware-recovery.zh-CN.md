# Raytac 固件恢复和校准兼容性

使用当前候选方案的[普通版／校准版文件与首板流程](../../hardware/usb-short-route/FIRST-ARTICLE.zh-CN.md)。普通版和校准版必须来自同一个候选固件包；保留参考主板的发行文件虽然同名，但 PCB 指纹不同。本轮修改固件和测试，PCB 接线及 C04 机械件沿用。

## 重新配对一个蓝牙主机

1. 使用 **Fn＋Q／W／E／R／T** 选择目标槽位，对应槽位 1～5（内部编号 0～4），随后松开槽位选择键。
2. 继续按住 Fn，**双击 Backspace**，两次按下间隔小于 **400 ms**；随后松开 Backspace 和 Fn。单击或一直长按不执行操作；基础层普通 Backspace 保留。
3. 在该主机上删除／忽略原来的 YETI60 配对，再使用此槽位重新配对。清除之前确认目标主机和槽位。

绑定调用 `BT_CLR`，仅清除**当前选中**的配对；没有调用 `BT_CLR_ALL`、整片擦除、设置重置或校准采集命令。其他主机槽位保留，主机端仍需删除旧配对。参见 [ZMK 官方蓝牙行为说明](https://zmk.dev/docs/keymaps/behaviors/bluetooth)。

该手势需要按键已经校准并正常工作。尚未校准的首板先使用 USB 校准终端；如果按键因硬件／扫描故障不可用，应先修复故障并使用 SWD／USB 恢复，不能依赖此按键手势。

## 什么情况下必须重新校准

校准契约 **v3** 纳入实际扫描驱动、目标 GPIO 模式辅助函数、可移植波形核心、校准实现及头文件、引脚表、主板／设备树／默认配置、依赖锁和校准 CMake 契约；还纳入生效的活动／空闲扫描周期和模拟前端门控配置。同一板型包内的普通版与校准版必须使用同一个标识；构建器读取实际扫描器编译命令和解析后的设备树进行核对。

修改 SAADC 增益、充放电脉冲实现、校准规则或生效的扫描参数，现在都会改变标识。原指纹包含 PCB、引脚、主板设备树和校准算法，却漏掉扫描驱动／核心实现，旧阈值可能被不兼容的改动继续接受。

第一次升级至 v3 会拒绝之前的校准。刷入配套校准版，完成 60 键采集并保存，再保留末尾 64 KiB 设置分区刷入配套普通版；两个镜像的应用起始地址均为零。整片擦除会删除校准和蓝牙配对，普通的单槽位清除不需要整片擦除。

`yeti_calibrate status` 在逐键表格之前输出 `calibration contract=0x... valid=...`，可与[候选固件检查中的 `calibration_contract_version`](../../hardware/usb-short-route/firmware/target-check.json)核对。版本不符、阈值越界或顺序错误，都会在启用按键上报前拒绝；304 字节 NVS 记录格式沿用。仅修改键位表不改变信号指纹。普通刷写会保留持久化设置，见 [ZMK 官方说明](https://zmk.dev/docs/config/settings)。

## USB 和按住按键时的行为

USB 配置被主机接受后，有线链路继续优先，并允许同时充电；配置接受之前关闭充电，输入维持 USB100。挂起时选择充电／输入高阻；拔线后由固定版本的 ZMK 端点实现选择可用的已配对蓝牙槽位。本次恢复功能沿用这些策略。

真实目标使用 ZMK 上报 HID。其端点切换处理会清空旧端点的报告，**切换主机或槽位后，应松开仍按住的键再重新按下**；不承诺把按住的键自动重放给新主机。可移植核心的报告回调在目标适配器中只是确认消费，实际没有用于发送 HID，不能仅根据该核心的主机模拟推断 ZMK 的切换行为。

## 验证范围

| 证据 | 执行或检查的内容 |
|---|---|
| [恢复测试](../audit/firmware-recovery.json) | 在固定构建容器中执行真实 CMake 指纹函数，检查源码／时序变动及仅修改键位表时的兼容性 |
| 同报告的原生手势测试 | 固定版本、未修改的 ZMK 双击行为 C 代码，在带地址／未定义行为检测的主机时间和行为派发接口上运行；单击、长按、慢击、被其他键打断均不清除；快速双击仅派发一次当前槽位清除 |
| [候选目标检查](../../hardware/usb-short-route/firmware/target-check.json) | 两版 ARM 构建、USB500 描述符、相同校准标识和真正解析后的 Fn／Backspace／槽位绑定 |
| [校准测试](../../hardware/usb-short-route/firmware/calibration.json) | 实际阈值生成器与持久化记录验证器，包含旧版本和损坏阈值的拒绝 |
| [USB 策略模拟](../../hardware/usb-short-route/firmware/simulation.json) | 真实适配器／核心配合模拟 USB／ZMK 接口，检查同时充电／有线优先及挂起／复位／拔线策略 |

这些测试没有执行真实配对／解绑持久化、USB 通信、射频时序或模拟波形。RTOS／射频抢占、实际 SAADC 时序、USB／充电／蓝牙负载下的阈值余量及实物按键行为仍须首板验证。扫描故障按设计锁存，排查后需复位；构建成功或主机模拟不能算实物验收。

初始化固定 west 工作区并启动 Docker 后，执行 `python3 scripts/test_yeti60_recovery.py`，再用 `python3 scripts/build_usb_short_firmware.py` 构建当前候选固件。测试编译固定版本的上游实现，主机接口没有替换生产固件的 ZMK 源码。依赖固定为 `wZuck/zmk@0862fc0f8c864834007986efcaf52f292ea6d37d`。
