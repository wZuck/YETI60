# NVS 写入中断与恢复模型

Raytac 检查现在将固定版本 Zephyr NVS 实现及实际校准加载函数接到有界 NOR 闪存模型。**14,795 次中断／恢复模型试验通过**，覆盖垃圾回收及恢复过程中再次中断。NVS 模型本身只增加验证，不改变生产固件或硬件。固件包升级以[当前入口](../../hardware/usb-short-route/firmware/README.zh-CN.md)为准；另行修补的空闲短按逻辑要求配套固件及重新校准。

这是软件恢复证据，不是电气断电测试。真实 NVMC、电池／充电供电欠压、闪存时序、寿命及真实蓝牙设置仍待首板验收。

## 实际输入与硬件模型

[测试脚本](../../scripts/test_yeti60_nvs_powercut.py)读取普通版 ARM 构建的实际配置与设备树，比对构建清单中的哈希，并在测试前核对全部已编译来源。依赖固定为锁文件中的 Zephyr `10ba6d0cb38bc3d258775d27982f707599320085`。

| 参数 | 数值及依据 |
|---|---|
| 预留设置分区 | 实际设备树中的 `0xF0000–0xFFFFF`，64 KiB |
| 此后端实际使用的 NVS 区域 | 八个 4 KiB 扇区，共 32 KiB；由 `SETTINGS_NVS_SECTOR_COUNT`、`SETTINGS_NVS_SECTOR_SIZE_MULT` 及分区上限计算 |
| 写入对齐 | 四字节；来自实际闪存设备树，且未启用单字节写入模拟 |
| 硬件擦除页 | 4 KiB；模型将一页拆成四字节片段，探查指定的部分擦除状态 |
| 全局 NVS 数据 CRC | 未启用，与两种 ARM 固件一致；校准数据另有独立 CRC |
| 校准数据 | 308 字节，使用当前板型包的真实标识及生产校验函数 |
| 其他设置哨兵 | 一个 64 字节不透明记录，不是真实蓝牙绑定或设置名称数据库 |
| 受保护区域 | `0xF0000` 以下的应用区，以及设置预留分区未使用的上半 32 KiB |

NVS C、公私头文件、CRC-8／CRC-32 和内建原子代码从固定来源原样编译。生产扫描器的 `load_calibration` 函数逐字提取，实际读取恢复后的 NVS 记录。设置后端和 Nordic 驱动只读取并记录哈希，用来核对配置来源，没有执行。闪存设备、互斥锁及重启接口采用模型。报告分别记录来源哈希。

闪存模型强制检查地址范围、对齐及未擦除时的 NOR 编程规则。模拟重启丢弃文件系统实例／锁，从保留的闪存字节重新挂载。每次接受校准都经过实际加载器的长度／版本／CRC／阈值检查并公布加载标志。每个场景还验证恢复后能再次保存完整校准并读回，以及其他设置哨兵仍然存在。

主要来源：[固定版本 NVS 实现](https://github.com/zmkfirmware/zephyr/blob/10ba6d0cb38bc3d258775d27982f707599320085/subsys/fs/nvs/nvs.c)、[设置后端区域计算](https://github.com/zmkfirmware/zephyr/blob/10ba6d0cb38bc3d258775d27982f707599320085/subsys/settings/src/settings_nvs.c)，以及 [Zephyr 对先写数据后写元数据及启动恢复的说明](https://docs.zephyrproject.org/latest/services/storage/nvs/nvs.html)。

## 注入方式与计算

对每个四字节写入或擦除模型片段，分别在片段前、处理前一／二／三个字节后、按 `0x55`／`0xAA` 位掩码处理后中断；另有一次在最终提交后、调用者尚未收到完成结果时中断。四字节擦除片段只是探查部分页内容的模型方法，不表示 nRF52840 支持四字节硬件擦除或按此顺序擦除页面。

因此，模型单位数为 `U` 时，试验数为 `6 × U + 1`：

| 场景 | 单位数 | 试验数 | 恢复旧记录／新记录／未校准 |
|---|---:|---:|---|
| 首次保存校准 | 79 | 475 | 0／1／474 |
| 覆盖已有有效校准 | 79 | 475 | 474／1／0 |
| 替换旧 304 字节记录 | 79 | 475 | 0／1／474 |
| 保存时回收非空扇区 | 1,204 | 7,225 | 7,224／1／0 |
| 先中断擦除，再中断恢复 | 1,024 | 6,145 | 6,145／0／0 |
| 合计 | | **14,795** | 全部通过哨兵及再次保存／回读检查 |

简单保存包括 77 个四字节数据单位（`308 / 4`）和两个分配记录单位（`8 / 4`），合计 79。垃圾回收基线由 103 次变化的填充数据更新形成。该次运行的保存包含两个扇区关闭单位、97 个活数据／元数据搬移单位、两个回收完成单位、1,024 个擦除片段，再加 79 个新记录单位：`2 + 97 + 2 + 1024 + 79 = 1204`。

恢复场景先在非空扇区擦除中途按 `0x55` 掩码制造第一次中断；随后在该状态重新挂载时，遍历所有恢复模型单位及指定方式制造第二次中断。它只验证这组有界的两次中断设置，不代表任意或无限次连续中断。

普通保存场景中的那一次新记录结果，来自最终提交完成但尚未返回确认的中断。首次保存和旧格式替换，其余情况可能保持未校准。原先已有有效校准时，这些指定中断保留完整旧记录或已提交新记录。模型没有公布部分阈值表。

两个临时改坏的 NVS 版本必须失败：先提交分配元数据再写数据，以及垃圾回收漏搬一个活哨兵。依赖工作区本身不修改。主机执行采用 ASan／UBSan。

## 重现与公开证据

在仓库根目录执行，需要主机 Clang、Python、固定依赖工作区及已构建的普通版／校准版：

```sh
python3 variants/raytac/scripts/check_yeti60_target.py
python3 variants/raytac/scripts/test_yeti60_nvs_powercut.py
```

[参考证据](../audit/nvs-powercut.json)记录配置、构建／设备树哈希、上游及项目来源哈希、五个场景和两个被拒绝错误版本。[候选证据](../../hardware/usb-short-route/firmware/nvs-powercut.json)在隔离候选目录中使用该板型标识独立生成。

只有测试改动、现有候选 ARM 产物仍匹配时，可以执行：

```sh
python3 variants/raytac/scripts/build_usb_short_firmware.py --host-tests-only
python3 variants/raytac/scripts/check_usb_short_firmware.py
```

仅重跑主机测试的模式先核对已有 ARM 来源及产物，再发布证据；它会拒绝过期固件输入，不能把已改固件来源当作已编译通过。新工作区或修改固件后仍需执行不带该选项的完整构建。总审查包含 NVS 模型，会拒绝缺少试验、配置不符、来源过期或冒称实物通过。

## 仍需验收

模型不执行 NVMC、射频同步闪存操作、Zephyr 调度器、完整设置名称分配／更新、真实蓝牙绑定、电压变化或磨损。它只选取指定的部分写入／擦除状态，不覆盖任意位顺序、全部损坏页或无限次连续中断。哨兵保留不证明真实蓝牙绑定已经通过实测。

首板按[开台流程](../../OPEN-BENCH.zh-CN.md)及[校准升级说明](calibration-storage.zh-CN.md)测量保存／擦除时的供电，检查普通复位保留，并结合实际电池／充电安排验证受控中断。确认恢复有效校准或明确未校准，后续仍能保存，应用与设置区域保持正确，真实蓝牙槽位也能保留。这些实物结果仍待完成。

首次总审查因目标固件 README 更新而发现指南关联哈希过期；[重检记录](../audit/nvs-guide-followup.json)保留初次失败矩阵，记录重新生成指南及逐项复验。其他已通过检查只在其相关输入保持不变并通过最终集成后沿用。
