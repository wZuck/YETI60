# USB 事件与充电控制归属审查

适用于当前 Raytac [首板包](../../hardware/usb-short-route/FIRST-ARTICLE.zh-CN.md)。普通版和校准版采用相同策略，保留已配置 USB 按键传输与充电同时运行。主机测试和链接 ARM 检查通过；真实 USB 时序、电流及充电切换仍需首板测量。

## 发现的问题及修补

原适配层只在 EC 扫描线程轮询 USB 状态时更新充电引脚。空闲扫描在帧间等待 30 ms，还要加上 ADC、模拟前端稳定及其他任务时间。控制台输出和设置写入也可能进一步推迟下一次轮询。这不适合作为挂起或取消配置的及时响应路径。

固定版本 Zephyr 对配置 1 和 `SET_CONFIGURATION(0)` 均发送 `USB_DC_CONFIGURED`，实际配置值放在 `params`。固定版本 ZMK 忽略该字节，仅检查其 HID 就绪标志可能在配置零后仍保留充电及有线就绪状态。

目标模块现在通过 `--wrap=usb_enable` 链接。包装函数将充电回调注册给原始 Zephyr `usb_enable`，随后把每次通知转发给原始 ZMK 回调。没有替换控制器内部回调、增加 USB 接口或修改依赖源码。配置字节为零、缺失或无效时，对 ZMK 转发 RESET，使其同时清除已接受配置标志。主机测试编译完整且未修改的固定版本 ZMK USB 源码验证此行为。

充电 GPIO 操作在 USB 状态回调内完成，先于 ZMK 排队通知，无需等待扫描或系统工作队列。固定版本 nRF 驱动本身通过 USB 工作队列分发通知；本次去掉了额外扫描延迟，并不意味着所有驱动／RTOS 延迟都已消失。扫描线程继续在 ZMK 系统工作队列中请求 USB 偏好，端点／报告切换仍在该处执行。过期的偏好请求会在切换前重新核对就绪状态。

## 状态及引脚表

下表为实际电平，CE 低有效。三根引脚均在 GPIO0：EN1=P0.06、EN2=P0.07、CE=P0.08。

| 事件／状态 | CE | EN1 | EN2 | 结果 |
|---|---:|---:|---:|---|
| 启动／已连接，尚未配置 | 1 | 0 | 0 | 禁止充电；USB100 系统输入 |
| 接受配置字节 1 | 0 | 1 | 0 | 允许充电；USB500 预算与系统共用；优先 USB 按键链路 |
| 挂起 | 1 | 1 | 1 | 禁充；输入高阻；系统改由电池供电 |
| 已有效配置后的恢复 | 0 | 1 | 0 | 恢复 USB500／充电 |
| 复位、拔线、配置零／缺失／无效 | 1 | 0 | 0 | 撤销配置；禁充；有输入时为 USB100 |
| 复位／取消配置后仅发生恢复 | 1 | 0 | 0 | 恢复事件本身不能重新授权充电 |
| USB 控制器错误 | 1 | 1 | 1 | 禁充；撤销配置 |
| GPIO 写入或 USB 启用失败 | 1 | 1 | 1 | 尽力禁充／输入高阻；锁定至重启 |

帧起始、接口和端点暂停相关通知不会单独授予配置或解除挂起。相同供电模式的重复事件不重写 GPIO。初始化可重复调用而不改变已生效引脚。充电引脚只有一个运行时持有者；扫描线程不再调用可移植核心的 `yeti_connections` 充电／报告演示，实际 HID 仍由 ZMK 管理。

切换模式前先禁用 CE。先将 EN1 拉高，再切换 EN2，避免短暂进入 EN1=0／EN2=1 的外部 ILIM 模式，包括挂起转复位。短暂中间模式仅为 USB100、USB500 或输入高阻，且禁止充电。GPIO 操作错误会中止正常序列，尝试禁充及输入高阻；软件不能保证物理引脚卡死或充电芯片损坏时的安全性，仍须独立电池保护。

**有意义的挂起／恢复验收必须连接合格保护电池包或适当的电池模拟器。** 不接电池时，输入高阻可能使系统断电。单独 USB 供电适合初步上电，不能证明电池支撑的挂起、恢复或蓝牙功能。普通只供电充电器不会枚举，因此不授权本设计的 USB500 充电。

## 证据及边界

- [USB 事件主机证据](../audit/usb-event-policy.json)：ASan/UBSan 下运行 11 个独立场景，编译实际适配层及完整、未修改的固定版本 ZMK USB 回调。覆盖配置零／空指针／无效值、不调用扫描轮询时挂起／复位／恢复、偏好工作受阻时的事件、过期排队请求、重复事件、逐步 GPIO 中间状态、GPIO 不可用、三次初始化及五次恢复写入逐一失败、USB 启用失败。
- [候选 ARM 检查](../../hardware/usb-short-route/firmware/target-check.json)：两版链接 USB500 描述符；解码 Thumb BL 目标，确认 ZMK 初始化实际调用包装函数，包装函数实际调用原始协议栈。仅存在符号不足以证明接入。
- [核心模拟](../../hardware/usb-short-route/firmware/simulation.json)：保留的可移植充电辅助函数同样避免外部 ILIM 中间状态；其中模拟 HID 报告不等于实际目标 USB／蓝牙传输。

首板验收时须连接实际合格保护包，对照 USB 挂起／复位／配置事件捕获 CE／EN1／EN2 与 USB 输入电流。检查主机取消配置、挂起／恢复、重复复位／重新枚举及边充电边打字。测量总回调／驱动延迟、输入瞬态、挂起电流和温度。主机测试及 ELF 检查不能证明这些实物结果或完整协议栈并发行为。

复现：`python3 scripts/test_yeti60_usb_events.py`，随后按[目标指南](../../firmware/target/README.zh-CN.md)构建、检查两套固件。事件主机测试需要 `~/.cache/yeti60-zmk-workspace/zmk` 下的固定版本源码及本机 Clang。本次源码变化会改变 v3 校准标识：使用同包普通版／校准版，从旧包升级时重新校准。

## 原始依据

- [固定版本 ZMK USB 回调](https://github.com/wZuck/zmk/blob/0862fc0f8c864834007986efcaf52f292ea6d37d/app/src/usb.c)：配置标志、状态回调及延后通知。
- [固定版本 Zephyr 配置处理](https://github.com/zmkfirmware/zephyr/blob/10ba6d0cb38bc3d258775d27982f707599320085/subsys/usb/device/usb_device.c)：配置零及配置字节转发；[nRF USB 驱动](https://github.com/zmkfirmware/zephyr/blob/10ba6d0cb38bc3d258775d27982f707599320085/drivers/usb/device/usb_dc_nrfx.c)：USB 工作队列分发。
- [TI BQ24074 原厂数据表](https://www.ti.com/lit/ds/symlink/bq24074.pdf)：EN1／EN2 模式、CE 及电源路径；输入高阻时保留电池至系统的路径。
- [USB-IF USB 2.0 规范](https://www.usb.org/document-library/usb-20-specification)：配置、挂起要求的依据；实际合规尚未验收。
