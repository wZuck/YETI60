# 矩阵、键位与 HID 链路审查

当前普通版与校准版都使用 **六个普通按键的 HID 槽位，修饰键另用位图**。扫描六十个物理按键、队列能容纳 120 次变化，不等于支持六十键同时上报。固定版本 ZMK 的 HKRO 实现中，已有六个普通键保持按下时，第七个键会被忽略；之后松开先前某键，也不会自动补报仍按住的第七键，需要松开再按。这是已执行代码呈现的软件行为，真实主机上的验收仍待首板。

本轮只增加测试与说明，不改变 PCB、固件字节、校准标识、六键报告格式或 USB／蓝牙策略。继续使用现有配套镜像，不因这项测试而重新采集校准。

## 执行的代码与模拟边界

运行器读取两种 ARM 构建实际解析后的 `zephyr.dts` 与 `.config`，先与构建清单核对哈希，再要求两版矩阵和两层键位完全一致。六十个基础键名及物理行列来自校准 CSV。Fn 层另列独立预期：重音键、F1～F12、Delete，以及 J／K／L／分号位置的左／下／上／右方向键。

固定 ZMK 版本 `0862fc0f8c864834007986efcaf52f292ea6d37d` 提供以下实际函数体：

- 物理布局的扫描回调、队列消费，以及矩阵查询函数。
- 键位层状态变化、按下时的层快照、绑定查询和位置分发。
- 普通按键、暂时切层及蓝牙命令处理、编码键值向事件的转换。
- HID 监听器的按下／松开函数及完整 `hid.c`。键盘／消费者报告结构、按键、用途和修饰键常量来自同一固定版本头文件。

测试夹具模拟队列操作、原位置映射、事件分发、设备查询、端点报告提交和时间。矩阵查询表及绑定表由实际目标设备树生成；断言检查真实 HID 报告状态和模拟端点收到的报告体。ADC 扫描由独立的[扫描线程测试](scan-control.zh-CN.md)覆盖；本运行器从扫描回调处注入边沿，不运行整套固件、实时系统、USB 栈、蓝牙栈或电脑 HID 驱动。

实际蓝牙行为解码函数通过模拟蓝牙接口执行五次槽位选择，行为路由器记录一次连击行为入口按下；不实现槽位／绑定存储或连击计时。绑定及固定版本连击实现另见[恢复测试](firmware-recovery.zh-CN.md)，真实配对仍待验收。传输切换和报告清空需要结合[USB 策略检查](usb-event-policy.zh-CN.md)及实物主机测试。

## 结果

| 场景 | 已检查的行为 |
|---|---|
| 基础层 | 全部 60 个物理位置按下／松开；59 个产生 HID 的位置和一个 Fn；共 118 次模拟 HID 报告提交 |
| Fn 层 | 按住 Fn，遍历其余 59 个位置；核对 Fn 键值及透明回落，五次槽位选择、一次连击入口；松开后报告及层状态清空 |
| 松键顺序 | 先按基础键再按 Fn，按基础键值松开；先按 Fn 再按层上按键，先松 Fn 后仍按原 Fn 键值松开；均无残留键值 |
| 同时按键上限 | 保留六个普通键，忽略第七键；松开再按后可进入报告，最终报告为空 |
| 未使用矩阵位置 | 十五个空位置均不产生位置事件或 HID 报告 |
| 全部松开 | 六十次按下后按相反顺序松开；报告、层状态和八个修饰键计数均归零；不声称六十键可同时进入 HID 报告 |

四个故意错误的版本均被拒绝：矩阵位置错移、缺少按下层快照、松键使用当前层、遗漏 HID 松键。主机程序使用 Clang 地址／未定义行为检测器。测试结果不代表实物送达、输入延迟、真实主机的多键处理或电气行为已通过。
