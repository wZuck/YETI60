# 校准记录完整性与升级

Raytac 两种固件现在均在 `yeti60/thresholds` 下保存带独立 CRC-32 的 **308 字节校准记录**。升级时使用配套的校准版／普通版，重新采集全部 60 键。旧 304 字节记录会被拒绝。保留设置分区，无需整片擦除；整片擦除还会删除蓝牙绑定。

本轮只改变固件及证据，不改 PCB、元件数量或制板文件。v3 信号指纹已包括校准源码／头文件和扫描器，修改后每套板型都会得到新标识。v3 是指纹合同名称，与记录字节布局分别定义。

## 发现的问题及修补选择

解析后的目标配置使用 NVS，**未启用 `CONFIG_NVS_DATA_CRC`**。NVS 对元数据做校验，但这不校验实际数据。此前阈值位翻转后，仍可能满足版本、范围及低阈值小于高阈值的检查而被接受。

Zephyr 文档说明，在现有存储上启用全局数据 CRC 会让旧记录失效。因此保持该全局选项不变，只保护键盘自己的校准数据，避免改变蓝牙及其他设置格式。构建脚本核对两个目标的实际选项。参见 [Zephyr NVS 文档](https://docs.zephyrproject.org/latest/services/storage/nvs/nvs.html)及[固定版本 NVS 实现](https://github.com/zmkfirmware/zephyr/blob/10ba6d0cb38bc3d258775d27982f707599320085/subsys/fs/nvs/nvs.c)。

| 字节偏移 | 长度 | 字段 |
|---:|---:|---|
| 0 | 4 | 当前板型／信号指纹，`uint32_t` |
| 4 | 150 | 五行十五列低阈值，`uint16_t`，按行排列 |
| 154 | 150 | 同顺序的五行十五列高阈值 |
| 304 | 4 | 前述字段的 CRC-32/ISO-HDLC |

CRC 显式按小端顺序处理版本、低阈值和高阈值，多项式为 `0xEDB88320`，初值和最终异或值均为 `0xFFFFFFFF`，不包含 CRC 字段自身。生产代码的静态断言检查 308 字节大小和 CRC 偏移。[实际实现](../../firmware/yeti60/calibration.c)由普通版与校准版共用。CRC 用于发现意外损坏，不提供身份认证，也不能发现所有可能的多位修改。

## 加载与保存

实际设置处理函数拒绝未知键、错误长度、读取错误／短读、指纹不同、CRC 不符、阈值反转／相等，以及超过 12 位 ADC 范围的阈值。全部检查通过后才公布已加载记录。坏记录不会覆盖此前有效的待处理记录。没有有效校准时，扫描器禁止按键上报，不会偷偷采用示例默认阈值。

工作线程形成候选阈值后计算 CRC。采集完整、有效且 `settings_save_one` 成功，才启用新阈值。保存失败时，运行时原先的 `saved` 记录不变，新采集不会被标为有效。[固定版本设置分发器](https://github.com/zmkfirmware/zephyr/blob/10ba6d0cb38bc3d258775d27982f707599320085/subsys/settings/src/settings.c)会记录并消化单个处理函数的错误，所以坏校准项不会终止后续普通设置处理；回归编译执行该分发函数的实际代码。

本轮不擦除设置、不清空绑定、不启用全局 NVS CRC，也不改变末尾 64 KiB 设置分区。新记录只增加四个数据字节；实际闪存分配还包括 NVS 元数据、对齐和设置名称，不能只按数据长度计算。主机测试不能证明真实断电、闪存寿命或电压裕量。

## 重现与证据

在仓库根目录执行：

```sh
python3 variants/raytac/scripts/test_yeti60_calibration.py
python3 variants/raytac/scripts/test_yeti60_scan_control.py
```

第一条需要主机 Clang／Python，第二条还读取固定版本 ZMK／Zephyr 工作区。两者均用 ASan／UBSan 执行原生 C。

| 证据 | 覆盖范围 |
|---|---|
| [校准报告](../audit/calibration.json) | 与独立 Python zlib 比对 512 份编码记录，包含 CRC 正确但阈值非法的记录；2,464 次单比特翻转、308 次整字节取反、2,433 个滑动全一 32 位突发均被拒绝 |
| 校准错误版本 | 取消 CRC 验证、取消 ADC 上限、改错 CRC 多项式均失败 |
| [扫描器报告](../audit/scan-control.json) | 逐字提取实际加载／保存／工作线程及固定版本设置分发器；旧 304 字节及其他错误长度、读取错误／短读、CRC／版本／范围错误、正确加载、坏记录不覆盖待处理好记录、保存失败保留运行时旧记录 |
| 扫描器错误版本 | 总计 15 个场景、17 个被拒绝错误版本，包含跳过长度／记录验证／完整读取／保存 CRC，以及错误传播单项加载错误 |
| [候选包证据](../../hardware/usb-short-route/firmware/README.zh-CN.md) | 隔离候选目录中独立测试，配套 ARM 固件标识、来源／产物哈希及不触及设置区的 HEX 地址范围 |

上述 CRC／扫描器测试不是物理闪存或 NVMC 断电测试。另有[固定版本 NVS 中断恢复模型](nvs-powercut.zh-CN.md)覆盖指定写入／垃圾回收／再次恢复中断，不能把它当作真实欠压、链路送达或运行中同时重载设置的验收。

## 升级与首板验收

1. 使用[当前候选固件包](../../hardware/usb-short-route/firmware/README.zh-CN.md)，按 [SWD 说明](../build/flashing.zh-CN.md)只写镜像涉及的应用扇区，保留 `0xF0000–0xFFFFF`。
2. 旧 304 字节校准被拒绝，重新采集前不上报按键。首板通过 USB 校准串口操作。将 `status` 与固件包的 `calibration_contract_version` 比较，不要复用不同包的阈值。
3. 采集松键和全部 60 个持按位置，保存并查看确认／状态。刷配套普通版时不整片擦除。重启检查全部按键及原有蓝牙槽位。
4. 首板测量保存／擦除时的电源电压，验证普通复位后的真实数据保留，并结合电池／充电供电安排验证受控写入中断。应恢复完整有效的旧数据或已提交的新数据，或明确进入未校准状态，不得悄悄使用错误阈值。记录真实闪存／驱动错误与恢复结果后再验收。

电池供方确认及[开台电气／功能检查](../../OPEN-BENCH.zh-CN.md)仍然适用。本轮没有刷写或测试实物。
